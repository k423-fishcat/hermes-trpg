## 一、整体架构

```
前端 (Vue/TS)
  ↓ SSE 流式
后端 (FastAPI + SQLAlchemy + AsyncOpenAI)
  ├── engine/
  │   ├── dm_agent.py       ← 核心：2334 行单文件 DM Agent
  │   ├── world_state.py    世界状态管理
  │   └── session.py        会话状态 + SSE 事件
  ├── knowledge_base.py     本地 RAG（TF-IDF + BM25）
  ├── character_card_manager.py  角色卡
  ├── dm_toolbox.py        工具箱
  ├── scenario_importer.py   剧本导入
  ├── long_term_memory.py    长期记忆
  ├── skills/               规则系统技能包（DnD5e/4e/COC/自定义）
  └── ...
  ↓
数据库（SQLAlchemy async） + 本地知识库（JSON + TF-IDF）
```

**设计模式**：典型的「LLM + Function Calling + 状态管理」架构，
所有状态变更通过工具调用完成，LLM 只负责叙事和决策。

## 二、核心亮点（值得借鉴的设计）

### 1. 三层硬约束体系

不是靠 system prompt 喊口号，而是三层防护：

**第一层：关键词触发强制检定**
```python
# L2178-2183
perception_verbs = r'观察|聆听|嗅\b|摸\b|翻找|侦查|张望|...'
if re.search(perception_verbs, player_input):
    messages.append({"role": "system", "content":
        "[系统提醒] B4规则：玩家正在进行感知行为。你必须判断DC...
         调用dice_roll。不允许仅用叙事代替检定。"})
```
玩家说"我看看/听听/摸摸"，自动注入「必须检定」的系统提醒。
**优点**：用关键词而不是语义判断，100% 可靠，零成本。

**第二层：每轮工具调用后场景校验**
```python
# L2214-2225：每轮工具调用后强制注入场景信息
scene_check = (
    f"[系统校验——每轮工具调用后强制执行] "
    f"当前位置: {ws.scene.current_location} | "
    f"时间: {ws.scene.current_time} | "
    f"天气: {ws.scene.weather} | "
    f"在场NPC: {', '.join(ws.scene.visible_npcs_here)}"
    f"\n如果你接下来的叙事会改变以上任何一项，必须先调用update_scene。"
)
```
防止「场景漂移」—— AI 跑着跑着忘了玩家在哪、现在几点。

**第三层：回合结束自动同步**
```python
# L2240-2245：end_of_turn 时自动同步 journal
ws.advance_turn()
ws.save()
await push_event(state, "journal_update", ws.to_player_journal())
```
不再依赖 AI 主动调用 `update_scene`，系统自动推进。

### 2. combat_round 工具：真正的「一键战斗」

`_exec_combat_round`（L1345-1458，113 行）做了这些事：

1. **自动读玩家攻击加值** — 从角色卡算，参数缺省时自动推导
2. **自动解析敌人** — NPC 卡 → 生物图鉴卡 → 缺省参数，三级兜底
3. **完整战斗结算** — d20 命中骰 → 伤害 → 敌人反击 → 结果描述
4. **自动写回状态** — 玩家受伤扣 HP（`_exec_update_state`）
5. **敌人伤害持久化** — 写回 NPC 卡 / 图鉴生物实体（`_persist_combat_damage`）
6. **附带元数据** — game_event 事件 + extras 字段（剩余HP/伤害量/是否死亡）

**关键点**：AI 只需要传 `player_action` 和 `enemy_name` 两个参数，
剩下的全部由工具自己算。AI 不需要知道 AC、伤害骰、HP，
也就不可能"编"错。

这是真正的「硬约束」——把数值计算完全封在工具里，AI 只描述结果。

---

### 3. 多规则系统技能包架构

`skills/` 目录下按规则系统拆分（DnD5e / DnD4e / COC / 自定义），
每个技能包定义：
- `system_prompt` — 该规则系统的系统提示词
- `tools` — 该系统可用的工具定义（JSON Schema）
- `max_tokens` / `temperature` / `history_rounds` — 该系统的 LLM 参数
- `rag_top_k` / `summary_limit` / `outline_limit` — 检索和摘要限制
- `combat_round` 等规则特定的计算函数

**优点**：加一个新规则系统只需要新增一个 skill 文件，
不用改核心逻辑。比我们的"模板驱动"更进一步——
我们的模板只驱动状态结构，它的 skill 驱动整个规则系统。

---

### 4. 本地 RAG 零 token 成本

```python
knowledge_base.retrieve(query, system, top_k, username)
```

- **方案**：jieba 分词 + TF-IDF + BM25 融合检索
- **零 token 消耗**：完全本地计算，不花 API 钱
- **按规则系统过滤**：DnD 搜 DnD 的知识库，COC 搜 COC 的
- **内容**：内置 5etools SRD + 361 个法术 + 31 个中文经典法术
- **可扩展**：支持用户上传知识库文档

对比我们的方案（关键词 + OpenViking 向量）：
- 本地 TF-IDF：零成本、快、但语义匹配弱
- 向量检索：有成本（或消耗外部资源）、语义匹配强
- **可以融合**：先用本地 TF-IDF 召回一批，再用向量 rerank

### 5. 剧本自动生成世界

- 导入文本（PDF/TXT/DOC/MD）→ 自动切分 → 生成摘要
- 自动生成世界大纲（世界观/主线/NPC/遭遇/规则）
- 自动识别规则系统（DnD5e/4e/COC/自定义）
- 自动提取 NPC/地点/生物/法术进入图鉴
- 生成过程 SSE 实时显示进度

这是「剧本 → 可玩世界」的自动化管线，
我们目前还需要手动整理世界书条目。

---

### 6. 记忆系统：短期 + 自动摘要 + 长期

- **短期记忆**：最近 5/10 轮对话（精简/标准模式）
- **自动摘要压缩**：超过阈值时自动压缩（`compress_memory_if_needed`）
- **长期记忆**：按用户隔离，持久化存储
- **记忆构建上下文**：`state.memory.build_context()` 注入到 system prompt

---

### 7. 三档模式适配

| 模式 | 回合记忆 | 检索数量 | token 上限 | 用途 |
|------|:-------:|:-------:|:---------:|------|
| 轻量（lite） | 5 轮 | 3 条 | 少 | 快速对话 |
| 标准 | 10 轮 | 5 条 | 中 | 正常跑团 |
| 深度思考 | 更长 | 更多 | 多 | 复杂场景 |

通过 `_play_mode(state)` 判断，所有注入和生成都按模式调整。

---

### 8. 过载保护机制

- **工具调用数限制**：每轮最多 3-5 个工具调用，防止无限循环
- **响应缓存**：相同输入直接返回缓存，避免重复 LLM 调用
- **反八股过滤**：`sanitize_narrative` 净化 AI 套话
- **自动存档**：每轮结束自动存，不需要 AI 管

## 五、总结

**TRPG-AI-DM 是一个完成度很高的中文单人 TRPG AI DM 产品**，
核心优势在于：

1. **硬约束做得扎实** — 关键词触发 + 每轮校验 + 自动同步，三层防护
2. **战斗一键结算** — 把数值计算完全封在工具里，AI 只描述
3. **剧本自动化** — 导入文本自动生成世界
4. **多规则系统** — skill 包架构，加新规则很方便
5. **本地 RAG 零成本** — TF-IDF + BM25，不花 token 钱

**我们可以快速抄的**：感知动词强制检定、每轮场景校验、战斗一键结算。
**值得长期跟进的方向**：skill 包架构、剧本自动生成、本地 TF-IDF 检索。
