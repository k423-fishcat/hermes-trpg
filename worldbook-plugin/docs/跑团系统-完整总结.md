# Hermes 跑团系统 — 完整总结

> 以 Hermes Agent 为核心的 D&D 5e 单人跑团 AI DM 系统。
> 五层分离架构，MCP 工具驱动状态，规则有据可查，长团记忆完整。
> **v2.9 更新：领域分包（spells/combat → domain/）+ 本地规则书快照（Open5e REST 拉取，rules/builtin/dnd5e/*.json）+ 规则书按需注入到 LLM 上下文（adapter/rules_injector.py）。**
> **v2.6-v2.8 更新：v2.8 规则书合规修复（spells/combat/inventory/rest） + v2.7 多规则系统（5e/3r/COC 7e） + v2.6 骰子引擎集中到 dice.py。**

---

## 一、系统定位

**是什么：** 一个跑在 Hermes CLI Agent 里的 AI 地牢主脑（DM）。你用自然语言跟 Hermes 对话，AI 扮演整个世界——NPC、环境、怪物、规则仲裁——背后是完整的游戏状态系统保证数值不飘。

**不是什么：** 不是独立的游戏应用，没有图形界面。它是"语言驱动的 TRPG 引擎"，一切交互都通过对话 + 工具调用完成。

**适用：** 单人 D&D 5e 跑团、模组预演、SOLO 团、DM 辅助。

## 二、整体架构：五层分离

```
┌─────────────────────────────────────────┐
│  ⑤ DM 大脑层（AI 人格 + 叙事能力）       │  SOUL.md + Skills
├─────────────────────────────────────────┤
│  ④ 记忆层（叙事积累）                    │  场次/选择/章节/里程碑
├─────────────────────────────────────────┤
│  ③ 状态层（动态运行时）                  │  玩家/NPC/战斗/时间/背包/法术
├─────────────────────────────────────────┤
│  ② 战役设定层（静态数据）                │  世界书/模组/怪物图鉴/角色卡
├─────────────────────────────────────────┤
│  ①.5 骰子引擎层（集中模块）              │  dice.py（本地 Python）v2.6 新增
├─────────────────────────────────────────┤
│  ① 规则查询层（只读，本地快照）          │  rules/RulesBook（v2.9+）
│                                        │  Open5e REST 拉取 → rules/builtin/<system>/*.json
└─────────────────────────────────────────┘
```

### 设计原则

1. **规则和设定分离** — SRD 规则通用所有战役，战役设定各自独立
2. **静态和动态分离** — 设定（世界书/怪物模板）不变，状态（HP/位置/进度）随时变化
3. **通用和专属分离** — SRD 数据公用，模组内容专属，不重复导入
4. **状态变更必须走工具** — AI 不能口述改数值，所有变化通过 MCP 工具记录到状态文件
5. **失败也要有趣** — 失败带来新麻烦/新信息/新转折，不是什么都不发生

### 4.1.5 骰子引擎层 ①.5（dice.py）— v2.6 新增

**位置：** `worldbook-plugin/dice.py`（~440 行）

**设计原则：** 所有掷骰逻辑集中在这一份，AI / slash 命令 / MCP 工具全部走这里。**纯 Python stdlib**（random + re），零外部 MCP / Go 进程依赖。

**11 个函数：**

| 语法 | 例子 | 函数 |
|------|------|------|
| 基础 | `d20`, `2d6`, `4d8` | `roll(expr)` / `roll_dice(n, s)` |
| 加减 | `d20+5`, `3d6-2` | `roll(expr)` |
| 多组 | `2d6+1d4+3` | `roll(expr)` |
| 优势/劣势 | `adv` / `dis`（D&D 5e） | `roll(expr)` / `roll_d20(adv/dis)` |
| COC 百分骰 | `d100` | `roll(expr)` / `coc_check(skill)` |
| 留高/留低 | `4d6kh3`（DnD 属性） | `roll(expr)` |
| 暴击 | `roll_damage("1d8", modifier=3, crit=True)` | `roll_damage` |
| 命中骰 | `roll_hit_dice(8)` / `roll_hit_dice_total("2d10", con_modifier=2)` | `roll_hit_dice*` |
| 治疗 | `roll_healing("2d4+2")` | `roll_healing` |
| 属性骰 | `roll_ability_scores("standard")` | `roll_ability_scores` |
| 先攻 | `roll_initiative(dex_modifier=3)` | `roll_initiative` |

**所有骰子函数返回结构化结果**（`{total, rolls, ...}`），AI 调用 `format_roll_result()` 可得到可读字符串。

**迁移记录：** v2.5 之前，6 个文件（combat / check_engine / characters / rest / spells / tools）里有 13 处 `import random` + `random.randint(...)` 内联调用。v2.6 起全部走 dice.py，行为完全等价。`interactions.py` 还清理了一个未使用的 `import random` 死代码。

**为什么不用外部 dice MCP：** 旧版文档声称用了 `trpg-dice MCP`（FastMCP，7 工具）和 `osg-dice MCP`（Go 编译），实际 worldbook-plugin 代码里 0 引用。新策略：不引 Go 进程（多故障点）、不起 FastMCP server（成本远大于 ~440 行 Python）、自研 dice.py 零依赖好测试。

### 4.2 战役设定层 ②

#### 世界书系统

```
data/worlds/<世界书ID>.json
```

**结构：** 条目化存储，每条有 ID、分类、关键词、内容、优先级、extras（扩展数据）

**分类：** 地点、NPC、物品、组织、剧情、怪物、规则、地下城、遭遇、任务……

**检索注入：**
- 每条消息自动检索相关世界书条目，注入到 AI 上下文
- AI 不用手动翻设定，场景描述自动符合设定

#### 交互点系统（Interactions）

世界书条目可嵌入**预设交互点**：
```
撬锁 → 巧手 DC15 → 成功/失败/大成功/大失败各有描述和后果
撞门 → 运动 DC13
检查陷阱 → 调查 DC12（隐藏，需要察觉DC10才能发现）
```

作用：让探索检定的 DC 和后果有据可依，不是 AI 临场编。

#### 怪物图鉴（Bestiary）

```
data/bestiary/<怪物ID>.json
```

- 只存自定义/模组原创怪物
- SRD 怪物从 dnd-rules MCP 查，不重复导入
- 战斗时实例化到状态中

#### 模组剧本系统

```
data/adventures/<模组ID>/
├── adventure.json   # 结构化模组数据
└── source/          # 原始源文件（可选，如 zim wiki）
```

**多格式导入：**
- ✅ 原生 adventure.json 格式
- ✅ Zim Desktop Wiki（Lost Mine of Phandelver 实测）
- 架构可扩展（加新格式只需写一个解析器）

**模组管理器：** 激活/停用/叠加，激活时自动导入到运行时系统（世界书/NPC/任务/遭遇）

**已导入模组：**
- **LMOP 失落矿坑** — 298 条世界书 + 28 NPC + 9 任务 + 68 遭遇
- **灰港** — 基础测试模组

#### 角色卡系统

完整的 D&D 5e 角色卡数据模型：
- 种族/职业/子职业/背景/阵营
- 六维属性 + 熟练加值
- 技能熟练 + 专长（双倍熟练）
- 豁免熟练
- HP / 命中骰 / AC / 速度
- 装备：武器/护甲/盾牌/饰品
- 法术：已知/准备/法术位上限
- XP / 升级计算（1-20 级完整 XP 阈值表）
- 背景故事/性格/理想/羁绊/缺陷

### 4.3 状态层 ③

所有运行时数据存在 `data/campaigns/<战役名>/state.json`。

#### 玩家状态

```
player: {
  name, level, xp,
  hp: { max, current, temp },
  abilities: { str, dex, con, int, wis, cha },
  ac, speed, proficiency_bonus,
  hit_dice: { total, used },
  spell_slots: { "1": 2, "2": 1, ... },
  death_saves: { successes, failures },
  inspiration, passive_perception,
  gold, conditions, concentration,
  spellcasting_ability,
  skills: { ... }
}
```

#### 背包与装备系统

**物品类型：** 武器/护甲/盾牌/药水/卷轴/工具/奇物/戒指/项链/帽子/靴子/手套/披风/腰带/消耗品/财宝/杂物

**装备槽位：** 主手/副手/身体/头部/脚部/手部/颈部/右指/左指/背部/腰部

**核心功能：**
- 物品增删、数量堆叠
- 装备/卸下，同槽位自动替换
- **AC 自动计算**（轻甲/中甲/重甲/盾牌/魔法加值，正确处理敏捷加值）
- 消耗品使用（药水治疗、获得 buff 等）
- 金币收支
- 负重统计（可选）

#### 法术系统

**法术生命周期：** 学习 → 准备 → 施放 → （专注维持）→ 法术位消耗 → 长休恢复

**核心机制：**
- 已知法术 / 准备法术 / 法术位 三层分离
- 施法属性自动计算攻击加值和豁免 DC
- 法术位向上兼容（低等级用完可以用高等级放低级法术）
- **专注机制：** 一次一个，受伤自动体质豁免（DC = max(10, 伤害/2)）
- 长休全部恢复，短休不恢复法术位（D&D 规则）
- 法术效果：治疗 / 伤害 / 状态效果（自动应用到状态）

#### NPC 系统

NPC 数据：位置、存活状态、态度值（-100到+100）、声望、交互记录、日程、已知信息、目标、**statblock 关联**

**Statblock 关联：** NPC 可以关联怪物图鉴中的 statblock（支持自定义属性覆盖），社交 NPC 也能进入战斗。

态度等级：
```
敌对 (<-50)  → 不友好 (-50~-10)  → 中立 (-10~+10)  → 友好 (+10~+50)  → 友善 (>+50)
```

#### 战斗追踪系统

**战斗流程：** 先攻 → 回合推进 → 伤害/治疗 → 状态效果 → 死亡跳过 → 战场日志

**伤害计算：** 带规则引用的完整过程——攻击骰/命中判定/伤害骰/抗性易伤免疫/最终伤害。

**特性：**
- 多怪物实例化（自动编号）
- 先攻排序（玩家和怪物一起排）
- 临时 HP、非致命伤害
- 死亡豁免
- 状态效果（中毒/束缚/震慑等）
- 战场日志记录每一次动作

#### 世界时钟

游戏内时间推进（时/日/月）、天气变化、定时事件触发。

#### 世界标记

战役级别的 flag 系统，记录"哪个门开了"、"哪个NPC死了"等世界状态变化。

#### 工程可靠性（状态持久化保障）

**原子写入**：所有状态写入采用「写临时文件 → fsync 刷盘 → os.replace 原子替换」模式，
即使进程崩溃也不会产生半截文件（Windows 下 `os.replace` 也是原子的）。

**Schema 校验**：基于状态模板派生的双向校验机制。
- 读取时：自动补缺失字段 + 修复类型不匹配（模板升级自动兼容）
- 写入前：结构检查，有问题打警告（不阻塞写入）

**双快照体系**：

| 类型 | 触发时机 | 保留数量 | 用途 |
|------|---------|:--------:|------|
| 版本快照 | 每次 state.update | 最近 20 个 | 撤销栈，小范围回退 |
| 命名快照 | 战斗开始前/场次结束/升级/模组激活 | 最近 30 个 | 关键节点存档，可回滚 |

**回滚安全**：回滚到命名快照前，会自动存一个当前状态的备份（`pre_rollback`），
防止误操作。回滚工具：`trpg_snapshot_rollback`。

155 行、7 部分：角色定位、叙述风格、DM 准则、骰子规则、世界边界、互动节奏、记忆与记录规范。

#### Skills（流程技能）

- **dnd-check** — D&D 5e 检定流程标准（要不要骰/DC设定/优势劣势/结果描述）

- 属性检定 / 技能检定 / 豁免检定 / 死亡豁免

#### 战斗数值硬约束（双重防护）

**为什么需要**：SOUL.md 里写了"状态变更必须走工具"，但这是软约束。
长团中 AI 可能因为上下文压力、注意力分散而"偷懒"直接口述数字。

**双重防护机制：**

**方案 A：事后校验（transform_llm_output 钩子）**
- 战斗激活时，AI 回复后自动扫描伤害/HP/命中数字
- 如果本轮没有对应工具调用记录，在回复末尾加 🛡️ 醒目警告
- 只在战斗激活时工作，非战斗完全不校验（状态机限定，不误伤）
- 实现：`combat_guard.py` + `transform_llm_output` 钩子

**方案 B：事前提示（pre_llm_call P0 注入）**
- 战斗激活时，在注入内容最前面加一段「战斗硬约束」提示
- 优先级 P0（比任务/世界书还高），保证 AI 先看到
- 内容：4 条硬性规则 + 当前战斗名称/回合数/轮到谁
- 效果：从源头强化"先工具后叙事"的习惯

**设计原则：**
- 用状态机（战斗是否激活）限定范围，不用语义猜
- 宁误报不漏报，但只警告不阻断
- 可通过配置 `combat_guard: false` 关闭

#### 上下文自动注入

每条消息前自动注入 7 类内容，**优先级配额制**：

| 优先级 | 内容 | 默认比例 |
|:------:|------|:--------:|
| P0（最高） | 战斗硬约束（仅战斗中） | 10% |
| P1 | 当前任务状态 | 15% |
| P2 | 世界书相关条目 | 40% |
| P3 | 前情提要（最近场次） | 25% |
| P4 | 剧情选择时间线 | 15% |
| P5 | NPC 关系摘要 | 15% |
| P6（最低） | 游戏时间与天气 | 5% |

总上限默认 5000 字符。高优先级先保证空间，不够了从最低优先级开始截断。

## 五、交互方式

### 5.1 对话驱动

所有交互都通过与 Hermes 的自然语言对话完成：

```
玩家：我推开酒馆的门走进去
DM：（描述场景）酒馆里烟雾缭绕……
```

AI 在幕后自动：
1. 检索相关世界书条目（酒馆/老比尔/灰港传闻）

## 七、核心工作原理

### 7.1 状态驱动原则

**"所有数值必须走工具，AI 只能读不能编。"**

错误做法 ❌：
```
玩家：我攻击哥布林
AI：好的，你砍中了，造成 6 点伤害，哥布林还剩 2 HP
（AI 自己编伤害和剩余 HP，下次可能忘了）
```

正确做法 ✅：
```
玩家：我攻击哥布林
AI：（调用 trpg_combat_damage 工具）
    → 工具读状态: 哥布林 HP 7
    → 工具计算: 6 穿刺伤害，无抗性
    → 工具写状态: 哥布林 HP = 1
    → 工具返回结果
AI：你短剑刺中哥布林，造成 6 点穿刺伤害！它踉跄了一下，但还没倒下。
（数值在状态里，下次攻击接着算）
```

**双重防护机制**（战斗场景）：
- **事前**：战斗激活时，注入内容最前面加「战斗硬约束」提示（P0 最高优先级）
- **事后**：AI 回复后自动扫描战斗数值，没有对应工具调用就加 🛡️ 警告
- 设计：用状态机（战斗是否激活）限定范围，不用语义猜，宁误报不漏报

### 7.2 自动注入原理

通过 Hermes 的 `pre_llm_call` 钩子，在每条用户消息发给 LLM 之前，自动插入相关上下文：

```
用户消息 → pre_llm_call 钩子 → 检索相关世界书/前情/任务
                         → 格式化成注入文本
                         → 拼接到用户消息末尾
                         → 发给 LLM
```

效果：AI 回复时"自动知道"世界设定和当前进度，不用每次手动喂。

### 7.3 规则仲裁原理

```
检定请求 → 从状态读属性/熟练 → 计算总加值 → 骰 d20
         → 判定结果（成功/失败/大成功/大失败）
         → 附加规则引用（说明依据什么规则）
         → 返回结构化结果
```

AI 拿到结果后用自然语言描述给玩家，但数字是工具算的。

## 十二、v2.8 规则书合规修复（2026-08-25）

D&D 5e PHB（玩家手册）合规性修复，4 个核心模块：

| 模块 | 修复内容 |
|------|---------|
| **`spells.py`** | 区分已知型施法者（邪术师/吟游诗人/术士） vs 准备型施法者（牧师/德鲁伊/圣武士） vs 法术书准备型（法师） |
| **`combat.py`** | `damage_vulnerabilities` 字段（伤害易伤双倍）；暴击规则：骰 2 倍伤害骰 + 加值仍只加一次 |
| **`inventory.py`** | `attune()` 实现魔法物品 attunement（3 件上限 + 同物品重复 attune 检测） |
| **`rest.py`** | 长休时 0-HP 角色 DC 10 死亡豁免（PHB "Resting" 章节）；Pact Magic 法术位长休全部恢复；exhaustion 长休减 1 级（与短休相同，但短休限制触发） |

**测试：** 测试套件从 142 扩到 **190 个**（+48 来自 rulebook 合规修复）。

**与多规则系统的关系：** 这些修复主要针对 D&D 5e 路径；D&D 3r / COC 7e 走各自的 `_rules_*.py` 适配器，部分模块（如 exhaustion）只在 5e 适用。
