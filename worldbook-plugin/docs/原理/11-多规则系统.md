# 11 — 多规则系统原理

> 规则适配器路由 + 本地规则书快照（v2.9+）
> 一个插件支持 D&D 5e / D&D 3.5 / COC 7e 三套规则

---

## 一、设计目标

加一套新规则系统 = 新建 1 个适配器 + 1 个模板 + 1 个规则书快照目录（`rules/builtin/<system>/*.json`），核心逻辑零改动。

---

## 一.五、规则书快照（v2.9+）

规则内容不再依赖 dnd-rules MCP 实时拉取，而是离线生成 JSON 快照，
由 `rules/RulesBook` 加载到内存。

### 文件结构（v2.9 末升级为按 edition 拆分）

```
rules/
├── rule_id.py           命名规则：rules.<system>.<category>.<slug>
├── schema.py            各 category 字段校验
├── loader.py            RulesBook 类（线程安全 RLock，cache_key = system:edition）
├── validate.py          校验脚本：python -m rules.validate
├── mcp_sync.py          Open5e REST 拉取 + 归一化（v1/v2 双版本）
└── builtin/
    ├── dnd5e/
    │   ├── 2024/        5e 2024 SRD（默认）
    │   │   ├── spells.json      339 条
    │   │   ├── classes.json     24 条（含 caster_type）
    │   │   ├── conditions.json  21 条
    │   │   ├── creatures.json   331 条（CR 0-30，含 actions_summary）
    │   │   ├── combat.json      7 条（手写 PHB 规则）
    │   │   ├── rest.json        3 条（手写 PHB 规则）
    │   │   ├── spell_slots.json 满/半/邪 1-20 等级表（手写）
    │   │   ├── checks.json      18 技能 + 6 豁免（手写）
    │   │   └── equipment.json   12 职业起始装备（手写）
    │   └── 2014/        5e 2014 SRD（兼容旧数据）
    │       ├── spells.json      319 条
    │       ├── classes.json     12 条
    │       ├── conditions.json  15 条
    │       ├── items.json       237 个魔法物品
    │       └── ... (其余手写与 2024 相同)
    ├── dnd3r/   (占位)
    ├── coc7e/   (占位)
    └── custom/  (占位)
```

**RulesBook 加载逻辑：**
- `load("dnd5e")` 默认读 `dnd5e/2024/`
- `load("dnd5e", edition="2014")` 读 `dnd5e/2014/`
- 查询 API（get/list/search）都支持 `edition` 参数

接入流程：
- `app_context._build_rules()` 自动 load("dnd5e", edition="2024")
- `check_engine._rule_reference()` 走 RulesBook 查 rule_id + phb_page
- `spells.cast_spell()` 返回 `rule_id` / `phb_page`
- `adapter/rules_injector.RulesInjector` 在 pre_llm_call 按玩家消息关键词自动注入相关规则
  （例：玩家说"长休" → 注入 `rules.dnd5e.rest.long_rest` 摘要）

**为什么是本地快照而不是直连 MCP？**
1. 速度：本地查询 < 0.1ms；MCP 远程 50-500ms（每条用户消息都跑注入）
2. 离线：SRD 公开固定，永不过期
3. 部署：少一个 MCP server 进程

**CI 钩子：** `tests/conftest.py` 在 pytest 启动时跑 `python -m rules.validate`，
任一文件 schema 不过就让 pytest 退出（returncode 2）。

## 一.六、中文名翻译（v2.10+）

D&D SRD 原数据全是英文，玩家和 AI 之间的对话是中文——直接注入英文规则
玩家看不懂，AI 也得二次翻译。所以拉取时 + 注入时做一次中文化。

### 数据流

```
Open5e API (英文)
   ↓ mcp_sync.normalize_spell_v1/v2(...)
rules/builtin/dnd5e/2024/spells.json  (name_en = "Fireball")
   ↓ loader 时 zh_mapping.translate(rule)
内存 RulesBook entry  (name_zh = "火球术", name_en = "Fireball")
   ↓ RulesInjector._format_rule()
注入片段标题： "**火球术 / Fireball** (`rules.dnd5e.spells.fireball`, PHB p.241): ..."
```

### 关键文件

| 文件 | 作用 |
|------|------|
| `rules/zh_mapping.json` | 静态映射表 `{category}.{slug} → 中文名`（897 条：342 spells + 24 classes + 21 conditions + 156 items + 354 creatures） |
| `rules/zh_mapping.py` | `get_zh(cat, slug)` 查表 + `translate(rule)` 自动从 rule_id 解析 |
| `rules/retranslate.py` | 离线补 `name_zh` 工具（不重跑 mcp_sync） |
| `rules/mcp_sync.py` | 拉取时对每个 normalize 函数 wrap `translate()`，内存里直接带中文 |
| `adapter/rules_injector.py` | `_format_rule()` 输出 "中 / 英" 双语标题（zh 含中文时） |

### 设计决策

1. **不引入 aliases 阶段**：直接 `name_zh + name_en` 双字段。`name_zh` 是用户能搜的中文名，`name_en` 保留原始英文（防止以后查 5etools 之类需要原文）。没有"昵称/曾用名/翻译别名"这种中间表——5e 中文社区常用名收敛度高，1 条映射够用。
2. **不覆盖已有中文**：`translate(rule)` 检测到 `name_zh` 已经含非 ASCII 就跳过（玩家手填的优先）。
3. **没映射的规则**：保留英文不报错（fallback 给空），`_format_rule()` 检测到 zh 还是英文时只显示英文名。
4. **注入标题格式**：`火球术 / Fireball` —— 玩家先看到中文，再附原文方便查证。AI 也按"中英对照"理解。

### 验证

- `tests/test_zh_mapping.py` 11 个测试：覆盖 mapping 加载 / translate 函数 / RulesBook 内存 zh 字段 / RulesInjector 双语输出
- `python -m pytest` 全量 221/221 通过
- `python -m rules.retranslate` 离线给已存 JSON 补 name_zh（不重跑 mcp_sync）

### 实际覆盖率（v2.10）

| 类别 | 5e 2024 | 5e 2014 |
|------|---------|---------|
| spells | 339/339 (100%) | 319/319 (100%) |
| classes | 24/24 (100%) | 12/12 (100%) |
| conditions | 21/21 (100%) | 15/15 (100%) |
| creatures | 263/331 (79.5%) | — |
| items | — | 133/237 (56.1%) |

### 后续扩展

- creatures 差 68 条（CR 9+ 顶级怪 + 一些变体如 lizardfolk shaman）—— 按需慢慢补
- items 差 104 条（剩余是一些"消耗品"和很冷门的装备）
- 5e 2024 玩家手册中文版（2025 译）出版后可批量覆盖剩余 21% 的怪

## 三、模板对比

| 字段 | D&D 5e | D&D 3r | COC 7e |
|------|--------|--------|--------|
| 角色根键 | `player` | `player` | `investigator` |
| 属性 | `player.abilities` | `player.abilities` | `characteristics` |
| 属性集 | str/dex/con/int/wis/cha | 同 5e | str/con/siz/dex/app/int/pow/edu/luk |
| 调整值 | (score-10)//2 | 同 5e | 无（原始 %） |

| 豁免 | 熟练加值通用 | fort/ref/will 分项 | SAN 值 |
| 攻击 | d20+调整+PB | d20+BAB+调整 | d100 vs 闪避 |
| 技能 | 熟练布尔 | rank（跨职业减半） | 0-99 % |
| 升级 | XP/level_up | XP/level_up | 无 |

## 五、路由（state/__init__.py）

```python
def _rules_adapter(self):
    t = (self.template_name or "").lower()
    if t in ("dnd3r", "dnd3.5", "dnd35e"): return _rules_dnd3r
    if t in ("coc", "coc7e", "coc7"):     return _rules_coc7e
    return _rules_dnd5e  # 默认
```

调用方 `get_modifier()` / `get_skill_modifier()` 完全透明，自动路由。

## 六、检定引擎的系统分流

`check_engine.roll_check()` 入口按 template_name 分流：

```
roll_check(...)
  ├── COC → _roll_coc_check（d100 vs 技能 + 奖励/惩罚骰）
  └── 5e/3r → d20 流程（规则适配器提供加值）
```

返回带 `system` 字段，`format_check_result` 按系统分发格式化。

## 七、D&D 3.5 细节（_rules_dnd3r）

- **BAB 进度**：职业驱动（战士 full / 牧师 3/4 / 法师 1/2），按等级推导
- **豁免**：Fort/Ref/Will，强豁免 `2+level//2`，弱豁免 `level//3`，加属性调整
- **技能**：rank 结构 `{"运动": {"ranks":4, "class_skill":true}}`，跨职业减半
- **AC**：总 AC / 接触 AC / 措手不及 AC 三部分

---

## 八、COC 7e 细节（_rules_coc7e）

- **派生属性**：
  ```
  HP = (CON + SIZ) / 10
  MP = POW / 5
  SAN = POW
  LUCK = POW * 5
  IDEA = INT * 5
  KNOWLEDGE = EDU * 5
  DODGE = DEX / 2
  ```
- **检定**：d100 ≤ 技能值，成功等级（极难/困难/普通）
- **无等级/升级**：调查员靠技能成长

---

## 九、D&D 5e 法术：已知 vs 准备（D&D 5e 专属，v2.8 修复）

`spells.py` 现在严格区分两类施法者（D&D 5e PHB 规则）：

| 施法者类型 | 学习上限 | 可用法术 |
|----------|---------|---------|
| **已知型（known）**（如邪术师、吟游诗人） | 等级表限制（2 + 法术等级×2 起） | 已学习列表中的法术 |
| **准备型（prepared）**（如牧师、德鲁伊、圣武士） | 等级表限制 + 长休后准备 | 准备列表中的法术（可换） |
| **法术位型**（法师） | 已学法术任意；每天从法术书准备 | 长休后从法术书准备 |

**影响**：此前所有职业都按"已学列表"算 → 现在准备型职业（牧师/德鲁伊等）必须 `trpg_spell_prepare` 后才能施放。

D&D 3r / COC 7e 不适用此区分（COC 无此概念；3r 直接按法术位/法师准备书机制，单独走 `state/_rules_dnd3r.py`）。

## 十、意图检测的多系统（v2.8）

`intent.detect_intent` 按 template_name 分发规则表：
- 5e → `intent/dnd5e.py`（18 技能 + 硬触发）
- 3r/coc → 暂空（规则表待实现）

换系统只需提供对应 `intent/<system>.py` 规则表，检测器/注入逻辑复用。

## 十一、扩展新系统步骤

1. 建 `data/templates/<system>.json`（状态结构）
2. 建 `state/_rules_<system>.py`（统一接口）
3. `state/__init__.py` 加路由映射
4. （可选）`intent/<system>.py` 加触发规则
5. （可选）`character_gen.py` 加生成器

**约 2-3 小时加一套完整规则系统。**
