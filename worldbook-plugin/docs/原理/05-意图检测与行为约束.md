# 05 — 意图检测与行为约束原理

> intent/ 包：在 AI 开口前扫描玩家意图，把"该检定/该攻击"从软约束变成硬约束
> 设计文档：docs/intent-detector-design.md

---

## 一、解决的问题

```
玩家：我看看房间里有没有异常
AI：你环顾四周，一切如常。      ← 没有掷骰，白看
```

工具层齐全（trpg_check/combat_*/spell_cast/rest），但调用靠 AI 自觉。
intent 层在 pre_llm_call 阶段扫描输入，命中规则就把"必须调用的工具 + 顺序"注入。

---

## 二、架构

```
Player Input
    ▼
Intent Detector     // 正则多命中扫描 → RuleEvent 列表（不淘汰）
    ▼
Action Rules       // 规则声明表（ActionRule dataclass，系统无关）
    ▼
Rule Events        // skill_check / attack / initiative / spell / rest / loot
    ▼
LLM（pre_llm_call 注入）
```

**核心原则**：
1. **多触发不覆盖** — 一条输入命中多个事件全保留，按规则顺序注入
2. **两级触发** — 强触发（必须检定）vs 弱触发（判断失败可能）
3. **规则与系统解耦** — 换系统只换规则表
4. **声明式** — 加规则 = 加一个 ActionRule

---

## 三、数据结构

```python
class ActionCategory(Enum):
    EXPLORATION, SOCIAL, COMBAT, SPELL, TRAVEL, REST, INVENTORY, LOOT, DOWNTIME

@dataclass
class ActionRule:
    name: str
    pattern: re.Pattern
    category: ActionCategory
    strength: int          # 1=强触发 2=弱触发
    order: int             # 执行顺序
    inject: str            # 注入文本
    event_type: str        # skill_check/attack/initiative/spell/rest/loot
    tool: str | None       # 应调用的工具
    ability: str | None    # 技能事件属性
    skill: str | None      # 技能事件名
    system: str | None = None      # 限定系统
    cooldown: int | None = None    # 冷却（预留）
    exclusive: bool = False        # 互斥（预留）
```

## 四、两级触发词表（5e 中文）

**一级强触发**（命中几乎必须检定）：

| 技能 | 触发词 |
|------|--------|
| Perception | 搜索/搜查/翻找/寻找/侦查/环顾四周/观察周围 |
| Investigation | 调查/分析/推理/找线索/破解/辨认痕迹 |
| Stealth | 潜行/偷偷/悄悄/溜过去/躲起来 |
| SleightOfHand | 撬锁/开锁/扒窃/顺走/摸包 |
| Athletics | 撞门/踹门/攀爬/举起/搬开/翻越 |
| ...（共 18 技能） | |

**二级弱触发**（只提示判断失败可能）：

```
看/看一眼/看看/听/听听/闻/摸摸/观察/张望/偷看/瞄
```

> 弱触发的关键：不强制，把"是否该检定"的判断责任显式交给 AI，
> 减少"我看了看地图"这类误报。

## 五、硬触发（非技能）

| 事件 | 触发词 | 工具 | 顺序 |
|------|--------|------|:---:|
| initiative | 开战/进入战斗/拔剑/偷袭/先发制人 | trpg_combat_start | 20 |
| attack | 攻击/砍/刺/射/挥剑/偷袭/斩/劈 | trpg_combat_damage | 30 |
| spell | 施放/施展/念咒/释放法术 | trpg_spell_cast | 40 |
| rest | 短休/长休/睡觉/扎营/过夜 | trpg_short_rest / trpg_long_rest | 40 |
| loot | 摸尸/搜身/翻尸体/搜刮/捡战利品 | trpg_inventory_add | 50 |

## 六、执行顺序（组合触发）

```
我潜行过去偷袭守卫
  ├── 命中 Stealth（skill_check, order 10）
  ├── 命中 Initiative（偷袭, order 20）
  └── 命中 Attack（偷袭, order 30）
  → 注入顺序：先潜行检定 → 再进先攻 → 后攻击
```

排序表：`skill_check 10 < initiative 20 < attack 30 < spell/rest 40 < loot 50`

---

## 七、注入文本

**强触发**：
```
[规则触发] 玩家行动涉及 Stealth（dex）。若该行动存在失败可能，
必须先调用 trpg_check 完成检定，再写叙事。禁止直接口述结果。
```

**弱触发**：
```
[规则提示] 玩家行动涉及感知类观察（Perception）。请先判断该行动是否存在失败可能；
若有失败可能，应调用 trpg_check 检定后再叙事；若只是陈述/无失败可能，可忽略。
```

**战斗触发**：
```
[规则触发] 玩家发起攻击。必须进入战斗流程：若尚未开战先 trpg_combat_start（含先攻），
再调用 trpg_combat_damage 结算。禁止直接口述攻击结果。
```

## 八、与 injector 整合

`injector._do_inject` 的 P0 段（与战斗硬约束同层）：

```python
from .intent import detect_intent
intent_text = detect_intent(user_message, state_mgr.template_name)
if intent_text:
    sections.append({"priority": 0, "name": "规则触发",
                     "content": intent_text, "max_ratio": 0.10})
```

多系统路由：`detect_intent` 按 `template_name` 分发，5e 返回触发文本，
3r/coc 规则表暂空（返回 ""）。

## 九、边界与分工

| 层 | 管什么 | 位置 |
|----|--------|------|
| **intent** | 事前：该检定/该攻击/该施法 | pre_llm_call |
| **P0 战斗约束** | 战斗中：先工具后叙事 | pre_llm_call |
| **combat_guard** | 事后：AI 别编数字 | transform_llm_output |

三层互补，各管一段，无重叠。

## 十、测试

`tests/test_intent.py`（22 用例）：
- 强触发：搜索→Perception、撬锁→SleightOfHand、潜行→Stealth
- 弱触发：看地图→提示不含"必须"
- 强覆盖弱：同技能强触发命中不再注入弱
- 硬触发：攻击/先攻/施法/休息/Loot
- 组合顺序：潜行偷袭 → skill_check < initiative < attack
- 不误报：打招呼/天气 → ""

> 当前全量测试套件 **190 用例** 全部通过（v2.8），intent 22 用例为子集。
