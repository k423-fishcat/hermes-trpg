# 03 — 检定引擎原理

> check_engine.py：所有检定的统一入口，三系统路由 + 规则引用 + 结果分级

---

## 一、定位

**"AI 不能口述判定结果，必须调用此工具。"**

`trpg_check` 是唯一检定工具（1 个），所有掷骰判定必须走它。返回结构化结果，AI 用自然语言描述，数字是引擎算的。

---

## 二、三系统路由

`roll_check()` 入口根据 `template_name` 自动分流：

```
roll_check(state_mgr, check_type, check_name, dc, advantage, ...)
  │
  ├── COC 7e（coc/coc7e/coc7）
  │     └── _roll_coc_check：d100 vs 技能值 + 奖励/惩罚骰
  │
  └── D&D 5e / 3r
        ├── 解析技能/属性/豁免/死亡
        ├── ability_mod = state_mgr.get_modifier()（规则适配器路由）
        ├── skill 检定 → get_skill_modifier()（5e=属性+熟练 / 3r=属性+rank）
        ├── 掷 d20（含 adv/dis）
        ├── 判定成功/失败/大成功/大失败
        └── 附加规则引用
```

返回带 `system` 字段（`dnd5e` / `dnd3r` / `coc7e`）。

---

## 三、检定类型

| check_type | 说明 | 加值来源 |
|-----------|------|---------|
| `skill` | 技能检定 | 规则适配器（5e=调整+熟练 / 3r=调整+rank） |
| `ability` | 属性检定 | 仅属性调整 |
| `save` | 豁免检定 | 5e=调整+熟练 / 3r=基础+调整（get_saving_throw） |
| `death` | 死亡豁免 | 特殊规则 |

---

## 四、D&D 5e 技能检定流程

```
1. 解析技能 → 属性键（SKILL_TO_ABILITY，如 运动→str）
2. ability_mod = (score - 10) // 2
3. skill 检定：total_bonus = get_skill_modifier(check_name)
   ├── 熟练 → 调整 + 熟练加值（+专长双倍）
   └── 不熟练 → 仅调整
4. 掷 d20：advantage → 2d20 取高 / disadvantage → 取低
5. total = nat_roll + total_bonus
6. 判定：
   ├── 自然 20 → 大成功
   ├── 自然 1  → 大失败
   ├── total ≥ DC → 成功
   └── 否则 → 失败
7. 附加规则引用（_rule_reference）
```

**v2.8 改进**：skill 检定从 5e 专用逻辑（proficiency 布尔）改为 `get_skill_modifier` 系统路由，修复了 3r 的 rank 加值计算。

---

## 五、COC 7e 检定流程（_roll_coc_check）

```
1. skill_value = get_skill_modifier(check_name)  # 直接返回技能 % 值
2. coc_check(skill_value, bonus_dice, penalty_dice)
   ├── 奖励骰 → 取最小十位
   └── 惩罚骰 → 取最大十位
3. 成功等级：大成功/极难/困难/成功/失败/大失败
4. 返回 system="coc7e" 的结构化结果
```

---

## 六、规则引用（_rule_reference）

每次检定附带规则依据，让 AI 知道"凭什么这么判"。例如：

```
📖 D&D 5e 规则：运动检定（STR）。若你尝试的力量相关技能在本职业熟练列表中，
   则检定加值 = 力量调整 + 熟练加值；否则仅力量调整。
```

**价值**：AI 的描述有规则背书，玩家能追溯。

---

## 七、结果分级描述

`format_check_result` 把结构化结果转成玩家可读文本：

```
💥 运动 检定 — 大成功！
──────────────
📊 难度: DC 15（中等）
➕ 加值: +6（力量调整+3，熟练+3）
🎲 1d20 = 18 + 6 = 24
✅ 成功（超过 DC 9 点）
📖 [规则引用]
```

**COC 版本**（system=coc7e 自动分发到 `format_coc_check_result`）：

```
✅ 侦查（技能 65）
──────────────
🎯 骰值: 38（个位 8，十位 [3]）
✅ 成功（超过技能 27 点）
```

## 十、v2.8 审计备注（PHB 合规）

**死亡豁免阈值修正**：审计发现死亡豁免若以 `total >= 10`（自然骰+调整值）作为成功条件不符合 PHB 规则。
PHB 规定死亡豁免应使用 `nat_roll >= 10`（**仅自然骰值，与调整值无关**）作为成功条件；
大失败仍为 `nat_roll == 1`，大成功仍为 `nat_roll == 20`（直接回 1 HP，无视结果数字）。

后续实现需在 `roll_check` 的 death 分支中改用 `nat_roll >= 10` 判定成功，理由是濒死状态下任何调整值都应被无视，
只比较裸骰是否过半。
