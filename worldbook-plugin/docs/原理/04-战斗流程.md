# 04 — 战斗流程原理

> combat.py：战斗追踪（先攻/回合/伤害/状态/日志）+ combat_guard.py：数值硬校验

## 一、战斗模型

```
战斗数据存 state.combat：
{
  active: true,
  name: "酒馆遭遇",
  round: 2,
  turn: 0,
  initiative_order: [          # 先攻顺序（高到低）
    { name: "玩家", initiative: 18, is_player: true, is_alive: true },
    { name: "哥布林1", initiative: 12, is_player: false, creature_ref: "goblin#1", is_alive: true }
  ],
  creatures: {                 # 怪物实例
    "goblin#1": { template_id, display_name, hp:{max,current,temp}, ac, conditions, ... }
  },
  log: [...]                   # 战斗日志
}
```

## 二、战斗生命周期

### 2.1 开始（start_combat）

```
start_combat(name, monsters, srd_monsters, player_initiative, monster_data_list)
  ├── 保存命名快照 pre_combat_<名>（回滚点）
  ├── 添加玩家（先攻 = 传入值）
  ├── 逐个添加怪物：
  │   ├── 本地图鉴 → instantiate（模板实例化）
  │   ├── SRD 怪物 → _convert_srd_to_template
  │   └── 预转换数据 → _instantiate_from_template
  │   └── 先攻 = dice.roll_initiative(init_bonus)
  ├── 按先攻排序（高→低）
  ├── 写日志
  └── 保存战斗（snapshot=True 关键节点）
```

### 2.2 回合推进（next_turn）

```
next_turn()
  ├── 跳过死亡单位
  ├── 到达列表末尾 → 新回合（round+1）
  └── 返回当前行动者 + 是否新回合
```

### 2.3 结束（end_combat）

```
end_combat(result)
  ├── 标记 active=False
  ├── 统计回合数/日志数
  └── 保存（snapshot=True）
```

## 三、伤害结算（damage_creature）— 核心

```
damage_creature(ref, amount, damage_type, source)
  ├── 先扣临时 HP（temp 优先）
  ├── 剩余伤害扣 HP
  ├── 抗性/易伤/免疫处理（damage_type 匹配）
  ├── 记录计算步骤 calc_steps（可追溯）
  ├── HP 归 0 → 标记死亡，从先攻跳过
  ├── 附带规则引用 rule_reference
  └── 写回状态 + 日志
```

**计算步骤示例：**

```
💥 哥布林1 受到 6 点挥砍伤害
📐 计算过程:
   • 攻击骰 d20 命中
   • 伤害 6 挥砍
   • 无抗性/易伤
   • 临时 HP 0 → 全扣
❤️ 剩余HP: 1/7
📖 [规则引用]
```

## 五、战斗数值硬约束（双重防护）

**为什么需要**：SOUL.md 写"状态变更必须走工具"是软约束，长团中 AI 会"偷懒"直接口述数字。

### 方案 A：事后校验（combat_guard.py）

```
transform_llm_output 钩子
  ├── 战斗激活？（状态机判断，非战斗不校验）
  ├── 扫描 AI 回复的伤害/HP/命中数字（正则）
  ├── 检查本轮有无对应工具调用（combat_damage/check/spell_cast...）
  └── 无工具调用 → 回复末尾加 🛡️ 警告（只警告不阻断）
```

**设计原则**：状态机限定范围（战斗激活才校验），宁误报不漏报。

### 方案 B：事前提示（injector P0）

战斗激活时注入最前面加「战斗硬约束」：
- 4 条硬性规则 + 当前战斗名称/回合数/轮到谁
- 从源头强化"先工具后叙事"

### 方案 C：意图检测（intent/，v2.8）

战斗**开始前**就触发（详见 05）：
```
我挥剑攻击守卫 → 注入"必须 combat_start + combat_damage"
```

**三层互补**：意图检测管"该进战斗"，P0 提示管"战斗中别乱来"，combat_guard 管"说完了别编数字"。

## 七、性能优化

`combat._save_combat` 默认 `snapshot=False`：
- 战斗中每次伤害/回合 → 只保存 state.json，不写版本快照
- 战斗开始/结束 → 写版本快照（关键节点）
- 10 回合战斗：10 次写盘 → 2 次快照，磁盘 I/O 大幅下降

## 八、v2.8 战斗规则补充（PHB 合规）

v2.8 起，战斗模块对伤害结算引入三项 PHB 5e 合规修正，由 `combat.py` 实现。

### 8.1 伤害易伤（damage_vulnerabilities）

`damage_creature` 现支持 creature 上的 `damage_vulnerabilities` 字段（`[str]` 伤害类型列表）。
当伤害类型命中易伤列表时，该次伤害**翻倍（×2）**，与抗性（减半）和免疫（无效）独立判定。

```
creature.damage_vulnerabilities = ["fire", "radiant"]
→ 受到 10 点火焰伤害 → 易伤翻倍 → 20 点
```

### 8.2 暴击（critical=True）

`damage_creature(ref, amount, damage_type, source, critical=True)` 新增显式 `critical` 参数。
暴击时所有伤害骰**翻倍**（PHB 5e：先掷再翻倍，固定加值不翻倍），
并由调用方在 `trpg_combat_damage` 工具透传（命中检定为 20 时由 AI 自行设置）。

### 8.3 抗 / 免 / 易伤独立应用

三类减伤效果**互不冲突、独立叠加**，应用顺序：

1. **免疫（immunity）** → 直接为 0 伤害，跳过后续
2. **易伤（vulnerability）** → ×2
3. **抗性（resistance）** → ÷2
4. **临时 HP（temp HP）** → 优先吸收
5. **当前 HP（current HP）** → 剩余伤害

注意：易伤与抗性**不互相抵消**（PHB 不允许"先减半再翻倍 = 原值"或"先翻倍再减半 = 原值"），
引擎按顺序独立应用，结算步骤写入 `calc_steps` 便于回溯。
