> narrative/ 包：编年史 / 任务 / NPC 关系 / 世界时钟 / 场次
> 所有数据经 StateManager 存储，走统一版本/回滚机制

## 一、记忆分层

| 层级 | 存什么 | 存在哪 | 怎么用 |
|------|--------|--------|--------|
| 世界设定 | 地点/NPC/物品/组织 | 世界书 JSON | 自动注入 |
| 角色数据 | HP/属性/装备/法术 | state.json | 工具读写 |
| 剧情状态 | 任务进度/世界标记/战斗 | state.json | 工具读写 |
| 事件事实 | 发生了什么 | 编年史 + 场次小结 | 前情提要注入 |
| 决策因果 | 选择+后果+影响 | 选择时间线 | 自动注入 |
| 阶段节点 | 章节里程碑 | 编年史章节 | 章节回顾 |
| DM 行为规范 | 该记什么 | SOUL.md | 系统提示 |
| 系统元记忆 | 架构/能力清单 | OpenViking | 跨会话 |

## 二、编年史（chronicle.py）

### 章节生命周期

```
new_chapter(title, desc)
  ├── 有当前章节 → 自动 end_chapter
  └── 创建章节（id, title, status=in_progress）

end_chapter(summary)
  ├── 标记 completed + 结束时间
  └── 清 current_chapter

add_event(event, importance)
  ├── 记入当前章节 highlights
  └── 全局保留最近 100 条
```

### 章节里程碑

```
add_milestone(title, desc, type)   # objective/turning_point/climax/resolution
update_milestone(id, status)       # pending/in_progress/completed/failed
```

### 章节结构化回顾（chapter_review）

章节结束时的 8 维度总结：目标进度 / 关键事件 / NPC 变化 / 物品获得 / 世界变化 / 成长 / 重大选择。

### 前情提要（recap）

```
📜 前情提要
📖 第 N 章: <标题>
• 事件1
• 事件2
```

## 三、任务系统（quests.py）

### 状态机

```
hidden → available → in_progress → completed
                  ↘ failed
```

### 任务结构

```
quest: {
  id, title, description, type(main/side), giver, rewards,
  steps: [{id, title, description, status}],
  current_step, status, notes, prerequisites
}
```

### 触发条件

`check_triggers()` 检查前置任务/世界标记，解锁新任务。

### 流程

```
add_quest → start_quest → advance_step（推进 current_step）
→ 全部完成 → complete_quest（结算奖励）
        ↘ fail_quest（失败）
```

## 四、NPC 关系（npcs.py）

### 数据结构

```
npc: {
  name, location, alive, attitude(-100~+100),
  attitude_level(敌对/不友好/中立/友好/友善),
  reputation, interactions, schedule, known_info, goals,
  statblock_ref    # 关联怪物图鉴（社交 NPC 也能进战斗）
}
```

### 态度等级

```
敌对 (<-50) → 不友好(-50~-10) → 中立(-10~+10) → 友好(+10~+50) → 友善(>+50)
```

### 交互记录

```
add_interaction(name, type, summary, attitude_delta)
  → 记入 interactions + 更新态度值
```

## 五、世界时钟（clock.py）

```
世界时间：年/月/日/时 + 时段（清晨/上午/正午/下午/黄昏/夜晚/午夜）
天气：字符串，可设置

advance_minutes/hours/days → 触发定时事件
add_event(时间, 描述)       → 定时事件
check_events()              → 触发到期事件
```

## 六、场次管理（sessions.py）

### 场次

```
start_session(title) → 新场次（number, start_time）
end_session(summary, key_events, end_location, next_hook, xp, gold, loot)
  ├── 写小结
  └── 保存命名快照 session_end_N
```

### 剧情因果链（选择）

```
add_choice(description, consequences, impact_tags, importance)
  ├── 记录重大选择（trivial/normal/major/critical）
  └── impact_tags 按关键词分类（关系/物品/世界/其他）

get_choice_timeline()  → 按重要度注入选择历史
```

## 八、数据存储

所有叙事数据在 `state.json` 的子键下，走 StateManager 统一读写：

```
state: {
  chronicle: {...},
  quests: {...},
  npcs: {...},
  world_time: {...},
  sessions: {...},
  world: { flags, encounters },
}
```

任意变更触发版本号 + 事件日志 + 快照（默认），回滚时叙事数据一起恢复。

**战斗路径快照优化**：combat 工具的 `_save_combat()` 默认传 `snapshot=False` 跳过版本快照（HP/回合数每回合都会跳一次，写盘过频），只在 `combat_start` / `combat_end` 这类节点性事件才 `snapshot=True` 形成存档。叙事变更（编年史/任务/NPC/选择）保持默认写快照，回滚时一起恢复。
