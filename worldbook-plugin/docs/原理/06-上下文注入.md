# 06 — 上下文注入原理

> injector.py：pre_llm_call 钩子，每轮自动注入相关上下文，优先级配额制

---

## 一、定位

玩家消息发给 LLM 之前，自动检索并注入相关上下文，让 AI "自动知道"世界设定和当前进度，不用每次手动喂。

---

## 二、注入流程

```
玩家消息
  ▼
pre_llm_call 钩子
  ├── 构造检索 query（基于消息 + 最近对话）
  ├── 收集 7 类注入内容（按优先级）
  ├── 优先级配额制分配空间
  └── 拼接到用户消息末尾
  ▼
发给 LLM
```

---

## 三、7 类注入内容（优先级配额制）

| 优先级 | 内容 | 默认比例 | 说明 |
|:------:|------|:------:|------|
| P0 | 战斗硬约束 / 规则触发 | 10% | 行为约束，最高优先 |
| P1 | 当前任务状态 | 15% | 最精简，必须完整 |
| P2 | 世界书相关条目 | 40% | 场景信息，必须有 |
| P3 | 前情提要（最近场次） | 25% | 长团记忆 |
| P4 | 剧情选择时间线 | 15% | 决策因果 |
| P5 | NPC 关系摘要 | 15% | 社交记忆（默认关） |
| P6 | 游戏时间与天气 | 5% | 最短 |

总上限默认 `max_chars=5000`。**高优先级先保证空间，不够从最低截断。**

---

## 四、优先级配额算法

```
sections 按 priority 排序（高在前）
remaining = max_chars
for sec in sections:
    max_for_sec = max_chars * sec.max_ratio
    available = min(max_for_sec, remaining)
    if len(sec.content) <= available:
        全放
    else:
        截断到 available-15 字符 + "...（已截断）"
        remaining = 0   # 后面的低优先级跳过
```

---

## 五、P0 战斗硬约束（方案 B）

战斗激活时，注入内容**最前面**加：

```
[战斗硬约束]
1. 伤害/HP 变更必须通过 trpg_combat_damage 等工具
2. 禁止直接口述数字
3. 当前战斗: <名> | 第 N 回合 | 轮到 <谁>
4. 先工具，后叙事
```

配合 combat_guard（事后校验）形成双重防护。

---

## 六、P0 规则触发（v2.8，intent 层）

```
[规则触发] 玩家行动涉及 Stealth（dex）...
```

多命中按规则顺序拼接（详见 05-意图检测）。

---

## 七、世界书注入（P2）

```
检索 query = 用户消息 + 最近 N 条对话关键词
  → retriever.search（OpenViking 向量 / 本地关键词 fallback）
  → format_for_injection 格式化为 markdown
  → 带交互点标注
```

**缓存**：同 query 结果缓存 `cache_ttl`（默认 60s），避免重复检索。

---

## 八、前情提要（P3）

`SessionManager.get_recap()` 生成：

```
📍 上次结束位置: 酒馆
📖 开场提示: 老比尔提到灰港以北的矿洞
📜 前情提要（最近 3 场）:
  第2场 - 矿洞探索
    • 击败哥布林头目
    • 发现秘密通道
```

---

## 九、性能设计

- **懒加载**：injector 的 5 个 manager 用 `@property` 按需实例化
- **世界书缓存**：query → (result, timestamp)，TTL 内复用
- **优先级配额**：总量封顶，防止上下文膨胀吃掉 token

---

## 十、可配置项（config.json）

| 配置 | 默认 | 作用 |
|------|------|------|
| `auto_inject` | true | 总开关 |
| `max_chars` | 5000 | 注入上限 |
| `max_entries` | 5 | 世界书条目数 |
| `enabled_books` | [...] | 启用的世界书 |
| `inject_quests/npcs/time` | ... | 各类开关 |
| `cache_ttl` | 60 | 检索缓存秒数 |
| `search_backend` | openviking | 检索后端 |

---

## 十一、v2.8 变更说明（2026-08-25）

v2.8 的 D&D 5e PHB 规则书合规修复（spells / combat / inventory / rest 4 个文件）**未触及 injector 路径**，本模块 v2.7+ 行为保持不变。注入管线仍按"7 类优先级配额制"工作，规则触发（P0 段六）继续由 `intent/` 层提供。
