# 00 — 系统总览

> 跑团系统 = Hermes CLI Agent + worldbook 插件
> 版本：v2.9（v2.8 规则书合规修复 + 领域分包 + 本地规则书快照）

---

## 一、系统定位

一个跑在 Hermes CLI Agent 里的 AI 地牢主脑（DM）。玩家用自然语言对话，AI 扮演整个世界，背后是完整游戏状态系统保证数值不飘。

**核心原则：状态驱动** — "所有数值必须走工具，AI 只能读不能编。"

---

## 二、架构：五层分离

```
┌──────────────────────────────────────────┐
│  ⑤ DM 大脑层（AI 人格 + 叙事能力）        │  SOUL.md + skills/
├──────────────────────────────────────────┤
│  ④ 记忆层（叙事积累）                     │  narrative/（编年史/任务/NPC/时钟/场次）
├──────────────────────────────────────────┤
│  ③ 状态层（动态运行时）                   │  state/（玩家/NPC/战斗/背包/法术）
├──────────────────────────────────────────┤
│  ② 战役设定层（静态数据）                 │  世界书/模组/怪物图鉴/角色卡
├──────────────────────────────────────────┤
│  ①.5 骰子引擎层（集中模块）               │  dice.py
├──────────────────────────────────────────┤
│  ① 规则查询层（只读本地快照）             │  rules/RulesBook（Open5e 拉取快照，v2.9+）
└──────────────────────────────────────────┘
```

**跨层约束：**
- **行为约束层**（intent/）：在 ⑤ 之前扫描玩家意图，注入"该检定/该攻击"硬规则
- **战斗校验层**（combat_guard）：在 ⑤ 之后校验 AI 回复里的数字是否走了工具

## 四、一次消息的处理流程

```
玩家输入
  │
  ▼
① pre_llm_call 钩子（injector.py）
  ├── 意图检测（intent/）→ 命中规则事件 → P0 注入
  ├── 战斗硬约束（combat 激活时）→ P0 注入
  ├── 任务状态 → P1 / 世界书 → P2 / 前情提要 → P3 / 选择 → P4 / NPC → P5 / 时间 → P6
  ├── 优先级配额制：高优先级先保证空间，超出从最低截断
  └── 拼接到用户消息末尾
  │
  ▼
② LLM（SOUL.md + Skills + 注入上下文）
  ├── 判断 → 调用 MCP 工具（trpg_check / trpg_combat_damage / ...）
  ├── 工具改状态（state.update → 原子写 + 版本快照 + 事件日志）
  └── 生成叙事回复
  │
  ▼
③ transform_llm_output 钩子（combat_guard.py）
  └── 战斗激活时扫描回复里的伤害/HP 数字
      → 有工具调用放行 / 无则末尾加 🛡️ 警告
```

## 五、数据流

| 数据 | 存哪 | 写路径 |
|------|------|--------|
| 战役状态 | `data/campaigns/<名>/state.json` | `state.update()`（单入口，原子写） |
| 版本快照 | `.../history/state_vN.json` | `update()` 默认写，战斗高频可跳过 |
| 命名快照 | `.../snapshots/*.json` | `save_named_snapshot()` |
| 世界书 | `data/worldbooks/*.json` | `WorldBookStore._save_book`（原子写） |
| 怪物卡 | `data/bestiary/*.json` | `Bestiary.add/update_monster`（原子写） |
| 角色卡 | `data/characters/*.json` | `CharacterManager.save`（原子写） |
| 配置 | `data/config.json` | `save_config`（原子写） |

## 六、关键设计决策

| 决策 | 理由 |
|------|------|
| 状态单入口 update() | 所有变更走同一路径，可记录事件日志 + 版本号 + 快照 |
| 双快照体系 | 版本快照（撤销栈）+ 命名快照（关键节点回滚） |
| 原子写所有 JSON | 崩溃不产生半截文件 |
| 规则适配器路由 | 加新规则系统 = 新建 1 个 _rules_*.py |
| 工具装饰器注册 | 加工具 = 1 个 @reg.tool() |
| 统一 AppContext | 消灭多套 singleton 缓存分裂 |

## 七、v2.8 规则书合规修复

2026-08-25 对齐 D&D 5e PHB 的 4 处核心规则，测试数从 142 提升到 190 通过：

| 模块 | 修复内容 |
|------|---------|
| `spells.py` | 区分已知型施法者（术士/吟游诗人/邪术师：只能从 `spells_known` 列表施展）与准备型施法者（牧师/德鲁伊/圣武士/法师/游侠：必须有 `spells_prepared` 才能施展）|
| `combat.py` | 新增 `damage_vulnerabilities`（易伤），伤害应用顺序：免疫 → 易伤 → 抵抗；新增 `critical` 参数，暴击时骰子数翻倍（D&D 规则）|
| `inventory.py` | 新增 `attune()` / `unattune()` / `list_attuned()`，强制 PHB 同调上限 3 件；同调新物品时若已满 3 件需先解调 |
| `rest.py` | 0 HP 角色禁止短休/长休（PHB 要求 ≥1 HP）；邪术师 Pact Magic 在短休恢复；长休降低 1 级 exhaustion；0 命中骰的角色不会获得 phantom dice |

**测试覆盖**：190 通过（v2.7 的 142 + 规则书修复新增 48）。
