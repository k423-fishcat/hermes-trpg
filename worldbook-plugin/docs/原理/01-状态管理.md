# 01 — 状态管理原理

> state/ 包：模板驱动 + 多战役 + 单入口更新 + 双快照 + 原子写

---

## 一、核心原则

1. **模板与数据解耦** — DnD 5e / 3r / COC 各有模板，代码不绑定具体字段
2. **多战役切换** — 每个战役独立目录、独立状态和历史
3. **单入口更新** — 所有状态变更走 `update()`，自动版本号 + Event Log + 快照
4. **模板升级兼容** — 读取时 Schema 校验自动补缺失字段

---

## 二、目录结构

```
state/
├── __init__.py        StateManager facade（对外 API 兼容）
├── _core.py           模板加载 + 状态 I/O（load/get/update/undo）
├── _campaigns.py      战役生命周期（create/switch/list/delete）
├── _snapshots.py      版本快照 + 命名快照 + 回滚
├── _rules_dnd5e.py    D&D 5e 规则适配
├── _rules_dnd3r.py    D&D 3.5 规则适配
└── _rules_coc7e.py    COC 7e 规则适配
```

`StateManager` 是薄 facade，所有方法委托给子模块，**60+ 调用方零修改**。

## 三、模板系统

模板定义状态的"结构蓝图"（`data/templates/*.json`）：

```json
{
  "name": "dnd5e",
  "display_name": "D&D 5e",
  "default_state": { ... },        // 默认状态结构
  "modifier_map": {...},            // 属性中英映射
  "skill_abilities": {...}          // 技能→属性映射
}
```

**角色根键差异：**

| 系统 | 角色根键 | 属性位置 | 特点 |
|------|---------|---------|------|
| D&D 5e | `player` | `player.abilities.{str,dex,con,int,wis,cha}` | 熟练加值 |
| D&D 3r | `player` | `player.abilities` | BAB/豁免独立 |
| COC 7e | `investigator` | `characteristics.{str,con,siz,dex,app,int,pow,edu,luk}` | 百分制 |

## 四、核心 I/O 流程

### 4.1 读取（load）

```
load()
  ├── 缓存命中？→ 返回 self._state
  ├── 加载模板 default_state
  ├── state.json 存在？
  │   ├── 读 JSON → validate_and_fill（Schema 校验 + 补缺失字段）
  │   └── 损坏 → logger.error + 备份 .json.broken + 从模板重建
  └── 不存在 → 从模板创建 + 保存
```

**Schema 校验（schema.py）**：
- 缺失字段 → 用模板默认值补
- 类型不匹配 → 尝试转换（str↔int），否则保留并警告
- 额外字段 → 记录不删除（允许扩展）

### 4.2 更新（update，单入口）

```
update(changes, reason, actor, snapshot=True)
  ├── 获取 RLock（防止并发写损坏 event_log / 快照）
  ├── 应用点路径变更（"player.hp.current": 15）
  ├── 记录事件日志（time/actor/path/old/new/reason）
  ├── 版本号 +1
  ├── event_log 截断（最近 500 条）
  ├── snapshot=True → 写版本快照（战斗高频传 False 跳过）
  ├── 原子写 state.json
  └── 释放 RLock
```

**并发安全**：`state.py` 拆为 `state/` 包后，`StateManager` 内部用 `threading.RLock` 守护所有写操作。多个钩子或异步任务同时调用 `update()` 不会交错 event log 条目，状态版本号单调递增。

**战斗性能优化**：`combat._save_combat` 默认 `snapshot=False`，战斗开始/结束才 `snapshot=True`。战斗 10 回合从 10 快照 → 2 快照。

### 4.3 回滚（undo）

```
undo(steps)
  ├── 计算目标版本 target_v
  ├── target_v==0 → 从模板重建
  └── 否则 → 从 history/state_v{target_v}.json 恢复
```

## 五、双快照体系

| 类型 | 触发时机 | 保留数 | 用途 |
|------|---------|:---:|------|
| **版本快照** | 每次 `update(snapshot=True)` | 20 | 撤销栈，小范围回退 |
| **命名快照** | 战斗前/场次结束/升级/模组激活 | 30 | 关键节点存档 |

**回滚安全**：`rollback_to_snapshot` 回滚前自动存当前状态为 `pre_rollback` 备份。

## 六、原子写入

所有 JSON 写文件统一走 `config.atomic_write_json()`：

```
写 tmp 文件 → fsync 刷盘 → os.replace 原子替换
```

Windows 下 `os.replace` 也是原子的。崩溃时要么旧文件完整，要么新文件完整，绝不产生半截文件。

应用范围：state.json / 版本快照 / 命名快照 / 世界书 / 怪物卡 / 角色卡 / 配置。

## 七、规则适配器路由

`StateManager` 按 `template_name` 自动选规则适配器：

```python
def _rules_adapter(self):
    t = self.template_name.lower()
    if t in ("dnd3r", "dnd3.5"): return _rules_dnd3r
    if t in ("coc", "coc7e"):    return _rules_coc7e
    return _rules_dnd5e
```

调用方 `get_modifier()` / `get_skill_modifier()` / `get_bab()` 等完全不用改，
新增系统只需新建一个 `_rules_*.py`（详见 11-多规则系统）。

## 八、战役管理

```
create_campaign(name, template, display_name)
switch_campaign(name)   → 切换 campaign_name + 清缓存
list_campaigns()        → 扫描 campaigns/ 目录
delete_campaign(name)   → 递归删除（危险操作）
```

全局单例 `get_default_state_mgr()` 统一所有模块访问，杜绝缓存分裂。
